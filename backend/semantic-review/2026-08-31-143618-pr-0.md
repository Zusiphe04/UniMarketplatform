It also removes the stale dependency on a monolithic “request 95” sequence while retaining the intentional, visible `PASTE_*` workflow. The revised instructions match the current server contracts. ## High-level view

Files 02–11 identify the login that can replace an expired token. Seller-only requests point to the post-approval login in file 02, preserving the fresh JWT needed to carry the `SELLER` role.

Checkout UUIDs now feed payment and escrow endpoints, while the declined and successful payment attempts each supply their own UUID to the matching detail request. The wording consistently separates these API IDs from human-readable `UM-*` order references.

Dependencies are expressed through filenames, response fields, and manual variables rather than request numbers or response scripts. This keeps the split files independent of numbering changes without altering the intended operator-driven workflow.
